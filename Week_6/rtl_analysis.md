# RTL Analysis
The RTL analysis focused on understanding the architecture, functionality, interfaces, and internal operation of the housekeeping_spi module before beginning physical implementation. This module serves as the housekeeping Serial Peripheral Interface (SPI) controller within the Caravel platform and acts as a communication bridge between external SPI transactions and internal configuration registers.

The top-level module, housekeeping_spi, exposes a clearly defined SPI interface consisting of chip select (CSB), serial clock (SCK), serial data input (SDI), and serial data output (SDO). Additional outputs provide decoded addresses, read and write strobes, pass-through controls, and register access signals. These interfaces allow the module to receive commands, decode addresses, transfer data, and control communication with both management and user SPI flash regions.

Internally, the design is centered around a finite state machine that controls SPI transaction processing. The state machine progresses through command, address, and data phases while monitoring the incoming serial stream. Depending on the command received, the module can perform register reads, register writes, streaming transfers, or enter pass-through modes that forward traffic directly to external flash devices. This architecture enables flexible SPI communication while maintaining a relatively compact implementation.

Several internal registers support the module's operation. Address registers store the current transaction address, shift registers manage serial data movement, and control registers track operating modes such as read, write, and pass-through functionality. Auto-incrementing address logic allows continuous data transfers without repeatedly transmitting new addresses, improving communication efficiency during streaming operations.

From a hierarchy perspective, the module is largely self-contained. It relies on definitions provided through defines.v and exists within the broader housekeeping subsystem that also includes supporting modules such as debug_regs.v. However, no complex submodule hierarchy is instantiated inside the design itself, making it straightforward to analyze and implement.

A notable characteristic of the RTL is its dual-edge clocking strategy. Input data and state transitions are processed on the positive edge of SCK, while output-related signals are updated on the negative edge. This arrangement ensures proper SPI timing by providing stable output data before the next sampling edge. The design also includes robust reset handling through a combined reset mechanism that returns the finite state machine to a known state whenever the chip select signal is deasserted or an external reset occurs.

Overall, the RTL analysis established a clear understanding of the module's functionality, dependencies, interfaces, and internal control structure. This understanding was essential for creating implementation constraints, interpreting synthesis and timing results, and validating that the final gate-level implementation preserved the intended RTL behavior.
